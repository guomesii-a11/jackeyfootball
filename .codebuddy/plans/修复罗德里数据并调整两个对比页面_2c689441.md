## 用户需求

1. 修正中场球员罗德里的数据：他应为西班牙人（国籍 Spain）、曼城球员、约 30 岁，而非当前导入得到的错误数据（Wrexham / England / 36 岁）。需重新检索其真实资料。
2. "球员对比"（综合数据对比）页面：默认展示所有球员一起比较，同时也支持跨位置手动选择特定球员进行对比。
3. "各数据对比"页面：直接对所有球员统一排名比较，不再按位置分组。

## 产品概述

修正 TheSportsDB 检索词导致的 Rodri 身份错配（真实 Rodri 需用 "Hernandez Cascante" 检索），并调整两个对比页面的展示逻辑：球员对比改为"默认全体雷达对比 + 位置筛选 + 跨位置自选"；各数据对比改为"全体统一排名"，去掉按位置分组。

## 核心功能

- 后端修复 Rodri 检索：增强数据源客户端的多候选消歧能力，并在导入脚本中增加"检索词覆盖表"，重新导入后 Rodri 变为曼城 / 西班牙 / 30 岁 / 中场，头像正常。
- 球员对比页：位置筛选 chips（全部 / 前锋 / 中场 / 后卫 / 门将），默认展示按位置筛选后的全体球员雷达对比；保留手动多选（可跨位置），提供"恢复全部"。
- 各数据对比页：删除按位置分组，全部球员按当前指标统一降序排名，柱长相对全局最大值。

## 技术栈

- 后端：FastAPI + SQLAlchemy 2.0 + httpx（均已存在，requirements.txt 已含 httpx）
- 数据源：TheSportsDB API v1（默认 Key "3"，免费免注册）
- 前端：Vue3 + TypeScript + Tailwind CSS + echarts（vue-echarts），现有组件 RadarCompare 复用

## 实现方案

### 总体策略

分三部分：① 后端增强 `thesportsdb_client.search_player` 的消歧与导入脚本的检索词覆盖，修正 Rodri；② 后端新增批量对比端点，供前端"全体对比"一次性取齐 `score_breakdown`；③ 前端改造 CompareView 与 DataRankingView 的展示逻辑。

### 关键技术决策

1. **消歧打分而非"取首个"**：原 `search_player` 在候选无精确 `strPlayer` 匹配时回退到 `players[0]`，导致 "Rodri" 误匹配成 "Jay Rodriguez"。改为多候选打分：精确 `strPlayer` 匹配 +10、`strTeam==prefer_club` +5、`strNationality==prefer_nationality` +5、含 `strThumb` +2，取最高分；同时导入脚本增加 `SEARCH_OVERRIDES = {"Rodri": "Hernandez Cascante"}`，用覆盖词检索，使真实 Rodri（曼城/西班牙/1996）被正确命中。新参数均带默认值，向后兼容现有调用。
2. **新增批量对比端点而非前端逐个请求**：原 `get_player` 每次都对全体球员计算 `_build_breakdowns`（O(N)），若前端对 22 人逐个 `getPlayer` 则为 O(N²)。新增 `GET /api/players/compare` 复用 `_build_breakdowns` + `PlayerDetail` 一次返回全部球员详情（含 `score_breakdown`），前端仅 1 次请求，性能更优且避免雷达图缺数据。
3. **CompareView 默认全体 + 位置收敛 + 跨位置自选**：`radarPlayers` 默认等于"按位置筛选后的全体球员"；当用户手动勾选球员时切到"自定义对比"（可跨位置，上限放宽到 6 人保证雷达可读），并提供"恢复全部"回到默认态。复用 `RadarCompare` 组件，无需改动。
4. **DataRankingView 去分组、全局排名**：删除 `ORDER`/`grouped` 分组计算，改为对全部球员按当前指标降序得到 `ranked`，`maxVal` 取全局最大，柱长 = `value/maxVal`；保留指标切换与 Top3 高亮。

### 性能与可靠性

- `search_player` 沿用既有超时/重试；打分择优选避免误匹配，单个查询异常由导入脚本捕获跳过、保留原值。
- 批量对比端点复用 `_build_breakdowns`（一次计算），避免前端 N 次单球员请求。
- DataRankingView 全局 `maxVal` 仅一次 `reduce`，无额外遍历；CompareView 用 `computed` 派生，避免重复渲染。
- 向后兼容：search_player 新参默认 None；mock seed 与评分引擎不变；前端仅改两个视图与一个 client 函数，不动 RadarCompare 组件，影响面可控。

## 实现注意事项

- 复用现有 `SessionLocal`、`_build_breakdowns`、`_normalize_breakdown`、`run_scoring_engine`、`getPlayers`、`getPlayersWithStats`、`POSITION_META`。
- 导入脚本遍历时把现有记录的 `current_club`/`nationality` 作为 `prefer_club`/`prefer_nationality` hints 传入，进一步防止误匹配。
- 重新运行 `SKIP_SEED=1 python3 import_real_data.py` 刷新；验证 Rodri 变为曼城/西班牙/年龄 30。
- 批量端点返回模型用既有 `PlayerDetail`，无需新增 schema。

## 架构设计

数据流：

- 修正 Rodri：import_real_data 用覆盖词+现有记录 hints 调 search_player → upsert 真实字段 → run_scoring_engine。
- 球员对比：前端 mount 调 getPlayersCompare()（→ /api/players/compare，后端复用 _build_breakdowns 计算全体 score_breakdown）→ radarPlayers（位置筛选/自选）→ RadarCompare。
- 各数据对比：前端调 getPlayersWithStats() → ranked（全局按指标排序）→ 统一排名列表。
